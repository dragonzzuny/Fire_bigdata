# 불씨예보 (K-Firebird)

한정된 소방 인력으로 **‘어디를·언제’ 먼저 점검·순찰할지** 데이터로 정해 주는 웹 서비스.

제6회 소방안전 빅데이터 활용 및 아이디어 경진대회 — 서비스 개발 부문 (박용준, 아주대학교)

소방안전 빅데이터(울산)로 500m 격자 단위 화재위험을 예측하고,
위험요인(SHAP) · 점검계획서 · 순찰 동선 · 소화전 사각지대를 자동으로 제시한다.

> 이 저장소는 기획서 제출 이후 원본 작업물이 유실되어 **기획서 기준으로 재구축**한 것이다.
> 소방안전 빅데이터 플랫폼에서 원본을 다시 받아 전 과정을 재현했고, 아래 수치는
> 모두 `scripts/04_train_eval.py` 의 실측값이다 (`outputs/evaluation.json`).
>
> | 지표 | 값 |
> |---|---|
> | 위험 상위 20% 포착률 (2014~2020 학습 → 2021 예측) | **68.5%** (95% CI 63.5%~72.9%) |
> | 단순 기준(전년 화재 순) 대비 | +5.0%p (CI +1.6~+8.0%p) |
> | 무작위 배정 대비 (PAI) | 3.43배 |
> | 도달 가능 최대치 대비 (PEI) | 79.4% |
> | 관할 제외 검증(LOGO) | 50.9% ~ 61.3% |
> | 울산 → 세종 이식 | 74.0% |
> | 가용 인력 제약 배분 개선 | +17.8%p (형평성 적용 186구역 기준) |
>
> **누적 화재 하나만으로도 68.4%가 나온다는 사실을
> 먼저 밝혀 둔다.** 포착률 자체는 이 서비스의 자랑거리가 아니다 — 값은 설명·이식성·
> 인력 제약 하 실행 계획에 있다. 자세한 것은 [docs/DATA_REALITY.md](docs/DATA_REALITY.md)
> 와 [docs/REPRODUCTION.md](docs/REPRODUCTION.md).

## 무엇을 하는가

```
원본 CSV ─▶ 주소 정규화 ─▶ 카카오 지오코딩 ─▶ 500m 격자 ─▶ 격자×연도 패널
                                                              │
                              ┌───────────────────────────────┘
                              ▼
                  LightGBM 위험예측 (시간분할 검증)
                              │
        ┌─────────────┬───────┴────────┬──────────────┐
        ▼             ▼                ▼              ▼
   위험 우선순위   SHAP 요인+규칙    순찰 시간·동선   소화전 사각지대
    (화면1)      → LLM 점검계획서      (화면3)        (화면4)
                   (화면2)
```

**분석 단위가 격자인 이유**: 공개 데이터에 건물번호·좌표가 없다. 주소에서 안정적으로
뽑아낼 수 있는 가장 낮은 해상도가 (시군구·도로명)이고, 이를 500m 격자로 모은 것이
현실적인 최적 단위다. 부산형 상세주소를 확보하면 건물 단위로 내려갈 수 있다.

**다만 실제 원본은 그보다 거칠다.** 학습 라벨인 화재발생현황은 도로명이 35%(울산
2005–2020)만 채워져 있고, 읍면동만 100% 채워져 있다. 그래서 지오코딩을 계층으로 만들었다:

```
1순위  시도 + 시군구 + 도로명    500m 격자와 해상도가 맞는다
2순위  시도 + 시군구 + 읍면동    항상 가능하지만 동 중심점이라 거칠다
3순위  시도 + 읍면동             시군구가 없는 세종 단층제 대응
```

`manifest_<city>.json` 의 `coverage.*.by_level` 에 **어느 단계로 얻었는지**가 남는다.
좌표 확보율만 말하고 그중 몇 %가 동 중심점인지 말하지 않으면 격자 해상도를
실제보다 좋게 주장하는 셈이 되고, 동 단위 뭉침은 **포착률을 부풀리는 방향**으로 작용한다.
원본과 기획서 가정의 차이 전체는 [docs/DATA_REALITY.md](docs/DATA_REALITY.md) 에 있다.

**위험 판단과 문서 생성을 분리한 이유**: 위험도는 모델이, 점검 항목은 규칙이 정한다.
LLM 은 이미 확정된 입력을 문장으로 옮기기만 한다. LLM 이 점검 항목이나 법령을
지어내면 그건 행정 문서의 오류가 되기 때문이다. 산출물에는 어느 경로로 만들어졌는지가
항상 함께 기록된다 — 사람이 쓴 문서와 기계가 쓴 문서를 나중에 구분할 수 없으면
검수 자체가 불가능하다.

### LLM 백엔드

`configs/config.yaml` 의 `llm.backends` 순서대로 시도하고, 되는 첫 번째를 쓴다.

| 백엔드 | 조건 | 측정 속도 |
|---|---|---|
| `cli` | `llm.cli.command` 의 실행파일이 PATH 에 있을 때 | `claude -p` 5.4초/건 |
| `api` | `llm.api.key_env` 환경변수에 키가 있을 때 (OpenAI 호환) | — |
| `ollama` | `localhost:11434` 가 응답할 때 | — |
| `rule_based` | 항상 | 즉시 |

기본값은 `claude -p` 다(이 머신 실측 5.4초/건, `codex exec` 6.0초).
다른 CLI 로 바꾸려면 `command` 만 고치면 된다.
프롬프트는 마지막 인자로 붙고, `{prompt}` 를 쓰면 그 자리에 치환되며,
`prompt_as_stdin: true` 면 표준입력으로 넘어간다.

```yaml
llm:
  backends: [cli, api, ollama, rule_based]
  cli:
    command: ["claude", "-p"]
```

> 확인된 제약: `gemini` CLI 는 개인 티어 지원 종료(`IneligibleTierError`)로 실패한다.

## 원본 컬럼이 안 맞을 때

플랫폼 CSV 의 컬럼은 한글이 아니라 영문 코드(`RCPT_DT`, `EMRG_RSCU_EMD_NM` …)이고
시도별로 조금씩 다르다. `01_inspect_raw.py` 가 실제 컬럼과 매칭 결과를 찍어 준다.

```
필수 emd            <- 'EMRG_RSCU_EMD_NM'
!! 필수 occurred_at  <- (못 찾음) 후보: ['RCPT_DT']
```

`configs/schema.yaml` 의 해당 항목에 **실제 컬럼명을 한 줄 추가**하면 끝난다.
파이썬 코드는 건드리지 않는다.

## 검증 프로토콜

하나만으로는 답이 안 나오므로 셋을 모두 돌린다.

| 프로토콜 | 묻는 것 | 구현 |
|---|---|---|
| 시간분할 홀드아웃 | 미래를 맞히는가 (2020까지 학습 → 2021 예측) | `model.temporal_validation` |
| 시간분할(이력만) | 스냅샷 피처를 빼도 되는가 | `features.history_only_columns` |
| LOGO (구·군 제외) | 한 지역을 외운 것인가, 옮길 수 있는 규칙인가 | `model.logo_validation` |
| 도시 이식 (울산→세종) | 새 도시에서도 되는가 | `model.transfer_validation` |

핵심 지표는 **상위 k% 포착률** — “위험 상위 20% 격자에 점검·순찰을 집중하면
그해 실제 화재의 몇 %가 그 안에서 발생했는가”. 항상 **베이스라인(‘작년에 화재가
많았던 순’)과 함께** 보고한다. 도시 화재는 원래 소수 격자에 몰려 있어서,
베이스라인 없이는 높은 포착률이 잘한 것인지 알 수 없다.

`04_train_eval.py` 는 **단일 피처만으로 줄 세운 결과**도 함께 낸다.
‘대상물 수 하나만 봐도 어느 정도 맞는다’는 한계를 우리가 먼저 숫자로 갖고 있기 위해서다.

## 이 저장소가 스스로 지키는 것

- **누수 차단이 코드로 강제된다.** 연도 t 의 피처는 t-1 까지의 화재만 쓴다.
  `features.assert_no_leakage()` 가 패널을 만들 때마다 실제로 검산하고,
  깨지면 파이프라인이 멈춘다.
- **좌표는 피처가 아니다.** 격자 좌표(gx/gy/lon/lat)를 학습에 넣으면 모델이
  ‘위험한 동네의 위치’를 외워 새 도시에서 무너진다. `features.NON_FEATURE_COLUMNS`
  가 이를 막고, 테스트가 그 사실을 지킨다.
- **화재 0인 격자를 버리지 않는다.** 버리면 포착률의 분모가 실제 도시와 달라진다.
- **동점을 입력 순서로 깨지 않는다.** 베이스라인은 화재 0 격자가 수천 개라
  동점 덩어리가 거대하다. 고정 시드 난수로 깬다.
- **깎여나간 양을 기록한다.** 좌표 확보율, 연도 추출 실패, 격자 배정 실패를
  `manifest_<city>.json` 에 남긴다. 숫자를 못 만든 것과 만들었는데 나쁜 것은 다른 문제다.
  좌표는 lon·lat 이 **둘 다** 있어야 확보로 센다(하나만 있으면 격자에 배정되지 않는다).
- **안 되는 것도 재고 기록한다.** 건축물대장 노후도를 읍면동 단위로 붙여
  측정했더니 개선이 없었다(−0.8%p, 신뢰구간 0 포함). 넣지 않았고 그 측정을
  `outputs/building_feature_eval_ulsan.json` 에 남겼다. 피처를 늘리는 것
  자체는 성과가 아니다.
- **스냅샷 피처의 시간 누수를 숨기지 않고 잰다.** 대상물·업소·소화전 데이터에는
  '언제부터 존재했는가'가 없어 과거 연도 행에도 현재 값이 들어간다. 데이터로는
  없앨 수 없는 한계이므로, `04_train_eval.py` 가 **이력 피처만으로도 한 번 더 검증**해
  스냅샷이 더한 몫(%p)을 함께 보고한다.
- **검증 실패를 성공처럼 보이게 하지 않는다.** LOGO 에 쓸 폴드가 하나도 없으면
  NaN 을 돌려주는 대신 멈춘다. '검증했는데 결과가 없다'와 '검증을 못 했다'는 다르다.
- **`--no-api` 는 진짜로 네트워크를 끊는다.** 환경변수에 키가 있어도 호출하지 않는다.
- **원본 좌표를 무조건 믿지 않는다.** 도시별 `bbox` 로 검증하고 경계를 벗어나면 버린다.
  세종 소방용수시설 좌표가 실제로 경북 방향을 가리켜서 넣은 장치다 —
  좌표가 '있다'와 '맞다'는 다른 문제다.
- **같은 화재를 두 번 세지 않는다.** 플랫폼이 주는 `_0000`/`_2021` 두 벌 중
  연도마다 더 온전한 쪽을 고르고, 무엇을 버렸는지 manifest 에 남긴다.
- **뭉개진 시각을 진짜처럼 쓰지 않는다.** `_2021` 파일은 시각이 전부 `000000` 이라
  시간대 분석에서 제외하고, 제외된 건수를 기록한다.

## 구조

```
configs/
  config.yaml      격자 크기, 연도 분할, 모델 하이퍼파라미터, 임계값
  schema.yaml      원본 CSV 컬럼 별칭 사전 (여기만 고치면 새 시도에 대응)
src/firebird/
  config.py        설정 로딩 (FIREBIRD_DATA_ROOT 로 데이터 루트 이동 가능)
  io_utils.py      인코딩 자동감지 CSV 적재 + 컬럼 별칭 해석
  addresses.py     주소 -> (시도, 시군구, 도로명) 파싱
  geocode.py       카카오 로컬 API + 디스크 캐시 + 시군구 생략 폴백
  grid.py          WGS84 -> UTM-K -> 500m 격자, 이웃, 셀 폴리곤
  features.py      과거화재·공간전파·용도/업종 구성 피처, 누수 가드
  dataset.py       원본 -> 격자×연도 패널 (+ manifest)
  model.py         LightGBM, 시간분할 / LOGO / 도시이식
  evaluate.py      상위 k% 포착률, 리프트, 10등급, 베이스라인 비교
  explain.py       SHAP 요인 (현장 용어로 번역)
  rules.py         업종·등급·현장여건별 점검 체크리스트
  llm.py           Ollama 점검계획서 (실패 시 규칙기반 폴백)
  hydrant.py       소화전 사각지대, 화재 급증 경보
```

## 한계 (기획서 6.기타와 동일)

- 공개 데이터에 건물주소·좌표가 없어 **도로·격자가 해상도 한계**다.
  부산형 상세주소를 확보하면 건물 단위·노후도(사용승인일)로 확장 가능하다.
- 실제로는 화재의 **3분의 2에 도로명이 없어 읍면동 중심점**으로 격자에 배정된다.
  이는 같은 동의 화재를 한 격자로 모아 **포착률을 부풀리는 방향**으로 작용한다.
- 원본에 **안전관리등급(특급/1급/2급)이 없어** 용도(MUSES_NM)와
  소방시설 설치대상 구분(TRGTOBJ_CLSF_NM)으로 대체했다.
- **2021년 화재는 시각이 없어** 시간대 분석에서 빠진다(연간 라벨로는 사용).
- **점검 이력은 결합이 불가**했다.
- 특정소방대상물·다중이용업소는 **현재 시점 스냅샷**이라 과거 연도에도 같은 값이 쓰인다.
  연도별 이력이 확보되면 이 부분이 개선된다.
- 순찰 동선은 **OSRM 공개 서버의 실제 도로 주행거리**를 쓰고, 관서 출발·복귀를
  포함한 왕복 거리를 2-opt·Or-opt 로 줄인다(지점 8개 이하에서 완전탐색 최적해와
  일치함을 시험으로 확인). 도로망 서버가 응답하지 않으면 직선거리 × 1.35 로
  물러나며, 어느 쪽을 썼는지 화면과 계획서에 표기된다.
- **소방관서 좌표 6개 중 2개, 119안전센터 28개 중 2개는 카카오 지도에 해당 관서가
  없어**(개칭·미등록) 관할 중심 좌표를 쓴다. 어느 쪽인지는 `coord_source` 에 남는다.

## 라이선스 · 유의

공개 데이터만 사용하며 개인정보를 다루지 않는다(도로·격자 집계 단위).
산출물은 예측 결과이며 법정 점검주기·관할 판단을 대체하지 않는다.
