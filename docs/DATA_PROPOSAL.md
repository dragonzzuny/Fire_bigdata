# 데이터 제안 (제출 양식용)

제6회 소방안전 빅데이터 활용 및 아이디어 경진대회 · 데이터 제안
박용준 (아주대학교 산업공학과 석사과정)

**제안 유형: ☑ 융합 데이터 제안** (2개 이상의 기존·외부 데이터를 결합)

아래 각 항목은 제출 폼에 그대로 복사해 붙일 수 있도록 500자 안에서 썼다.
바탕이 된 실측치와 원문은 뒤의 「부록」에 있다.

## 데이터 설명

```
소방과 건축의 자료가 같은 건물을 저마다 다른 이름으로 부르고 있어 서로 붙지 않습니다. 이 데이터는 새로운 사실을 만드는 것이 아니라, 흩어진 자료를 같은 건물끼리 이어 주는 연결표입니다.

한 줄에 특정소방대상물 하나가 들어가고, 그 옆에 소방이 쓰는 대상물관리번호와 국토교통부의 건축물대장 관리번호, 필지고유번호(PNU), 다듬은 주소와 좌표를 함께 싣습니다. 무엇을 근거로 이었는지와 그 확신의 정도, 언제부터 언제까지 유효한지도 같이 남깁니다.

신축과 멸실이 반영되도록 해마다 한 번 이상 갱신하며, 유효기간이 있어 지난 시점의 모습도 그대로 되살릴 수 있습니다. 전국을 대상으로 하되 시·도 단위로 나누어 만들 수 있고, 형태는 CSV입니다.
```

## 융합 대상 데이터 (최소 2개 · 최대 5개)

| # | 데이터명 | 보유기관 |
|---|---|---|
| 1 | 특정소방대상물 현황 | 시·도 소방본부 (플랫폼 개방 중) |
| 2 | 화재안전특별조사(점검이력) | 시·도 소방본부 (플랫폼 개방 중) |
| 3 | 건축물대장 표제부 | 국토교통부 (건축HUB·공공데이터포털 개방 중) |
| 4 | 도로명주소·건물정보 | 행정안전부 (주소기반산업지원서비스) |
| 5 | 화재발생현황 | 시·도 소방본부 (플랫폼 개방 중) |

앞의 세 가지가 핵심이다. 네 번째는 주소 표기를 맞추는 데 쓰고, 다섯 번째는
이은 결과가 맞는지 확인하는 데 쓴다. 다섯 가지 모두 이미 공개되어 있고,
없는 것은 서로를 잇는 열쇠뿐이다.

## 융합 방법

```
필요한 열쇠는 기관마다 이미 가지고 있는데, 서로에게 알려 주지 않은 상태입니다. 화재안전조사 자료에는 대상물관리번호가 빠짐없이 들어 있고 건축물대장에는 전국에서 유일한 건물 번호가 있는데, 정작 특정소방대상물 자료에는 둘 다 없습니다.

그래서 먼저 소방이 이미 쓰고 있는 대상물관리번호를 특정소방대상물 자료에 한 칸 넣습니다. 이것만으로 점검이력이 곧바로 붙습니다. 다음으로 건축물대장을 잇습니다. 소방이 가진 건축물관리번호를 먼저 쓰고, 없으면 지번을 PNU로 바꾸어 잇고, 그래도 안 되면 행정안전부 주소로 표기를 맞춘 뒤 잇고, 마지막으로 좌표가 가깝고 주용도가 같은 건물을 찾습니다. 어느 방법으로 이었는지는 줄마다 적어 둡니다.

끝으로 화재발생현황과 맞춰 결과를 확인합니다. 못 이은 줄은 비워 둡니다.
```

## 활용 목적 및 활용방안

```
지금은 점검이 화재를 줄이는지 확인할 방법이 없습니다. 점검 기록이 어느 건물의 것인지 알 수 없기 때문입니다. 열쇠가 생기면 점검을 받은 건물과 받지 않은 건물의 이후 화재를 견주어 볼 수 있고, 법정 점검주기를 손볼 근거와 예방 예산이 실제로 무엇을 바꿨는지를 숫자로 댈 수 있습니다.

점검 대상을 고르는 일도 달라집니다. 지금은 지역 단위로만 위험을 가늠하지만, 건물 단위로 내려가면 예측한 대상이 그대로 점검할 대상이 되어 결과를 곧바로 계획서로 옮길 수 있습니다.

플랫폼이 이미 가지고 있는 유동인구, 화재보험 위험도, 소방 IoT 자료도 같은 열쇠 하나로 건물에 붙습니다.
```

## 제안 배경 및 차별성

```
이번 대회 출품작을 만들다가 실제로 막힌 자리입니다. 울산 화재안전특별조사 887,753줄에는 대상물관리번호가 빠짐없이 들어 있는데, 정작 특정소방대상물 자료에는 그 번호도 주소도 없습니다. 이을 방법이 없어 88만 줄을 통째로 덮어 두고 작업했습니다.

같은 벽에 미국도 부딪혔습니다. 애틀랜타 소방의 Firebird와 뉴욕 FDNY가 나란히 가장 어려웠던 점으로 꼽은 것이 부서끼리 공유하는 건물 번호가 없다는 것이었고, 둘 다 주소 글자를 맞추는 방식으로 돌아간 뒤 그 오차를 한계로 남겼습니다.

미국이 풀지 못한 이유는 전국을 아우르는 건물 번호가 아예 없어서입니다. 한국에는 건축물대장 관리번호가 이미 있습니다. 새로 모으자는 제안이 아니라, 이미 가진 번호를 서로 알려 주자는 제안입니다.
```

## 데이터 확보·구축 방안

```
첫 단계에는 돈이 들지 않습니다. 특정소방대상물 자료에 대상물관리번호 한 칸을 더하는 일입니다. 이 번호는 소방이 이미 쓰고 있습니다. 화재안전조사 자료에 빠짐없이 실려 있는 것이 그 증거입니다. 사람에 관한 정보가 아니라 행정용 번호라 공개에 걸림돌도 없습니다. 이 한 칸으로 묻혀 있던 점검이력 88만 줄이 살아납니다.

두 번째 단계인 건축물대장 연계는 국토교통부 건축HUB에서 이미 열려 있는 자료를 씁니다. 소방이 가진 건축물관리번호, PNU, 행정안전부 주소, 좌표와 용도의 순으로 이어 갑니다.

무엇보다 못 이은 줄은 비워 둡니다. 억지로 붙인 한 줄이 그 자료로 만든 분석 전부를 의심받게 합니다. 얼마나 채웠는지보다 어떻게 이었는지를 밝히는 편이 낫습니다.
```

## 기대효과

```
점검이 화재를 줄이는지 처음으로 재 볼 수 있게 됩니다. 법정 점검주기를 조정할 때, 예방 예산의 성과를 설명할 때, 소방시설 지원 대상을 고를 때 건물 단위의 근거가 생깁니다.

플랫폼에도 남는 장사입니다. 소방안전 항목에는 240건이 올라 있는데 화재위험분석 항목은 한 건뿐입니다. 자료를 더 늘리기 전에 이미 올라 있는 240건이 서로 붙게 하는 편이 이용자에게 더 값집니다. 이용자마다 주소를 각자 다듬어 맞추던 수고가 사라지고, 같은 자료를 쓰고도 사람마다 다른 답이 나오는 일도 줄어듭니다.

화재보험 요율 산정이나 소방시설 관리업체의 대상물 이력 관리처럼 플랫폼 바깥에서의 쓰임도 함께 열립니다.
```

이 제안이 어긋날 수 있는 지점도 밝힙니다. 소방 안에 건축물관리번호가 없을 수 있습니다. 그렇더라도 첫 단계만으로 88만 줄이 살아나므로 두 단계를 나누어 드립니다.

## D. 이 제안이 우리 출품작을 어떻게 바꾸는가

출품작 **불씨예보(K-Firebird)** 는 500m 격자 단위로 화재위험을 예측해 상위 20%
구역으로 실제 화재의 68.5%를 포착한다. 격자에 머문 이유는 건물 단위로 내려갈
키가 없어서다.

건축물대장을 **읍면동 단위**로라도 붙여 노후도 피처를 만들어 측정해 봤으나
개선이 없었다(−0.8%p, 95% 신뢰구간 −2.53 ~ +0.98%p). 읍면동 단위로는 같은 동의
격자가 모두 같은 값이 되어 격자를 가르지 못하기 때문이다. **건물 단위 키가
있어야 풀리는 문제**라는 것을 측정으로 확인했다.
