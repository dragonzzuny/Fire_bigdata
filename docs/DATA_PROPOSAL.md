# 데이터 제안 (제출 양식용)

제6회 소방안전 빅데이터 활용 및 아이디어 경진대회 · 데이터 제안
박용준 (아주대학교 산업공학과 석사과정)

**제안 유형: ☑ 융합 데이터 제안** (2개 이상의 기존·외부 데이터를 결합)

> 아래 각 항목은 제출 폼에 **그대로 복사해 붙여 넣도록** 500자 이내로 작성했다.
> 근거가 되는 실측치와 원문 인용은 「부록」에 있다.

## 데이터명

```
소방대상물 통합식별키 데이터셋 (특정소방대상물–화재안전조사–건축물대장 연계)
```

## 데이터 설명

```
기존 데이터를 대체하지 않고, 흩어진 소방·건축 데이터를 하나의 건물로 이어 주는
연계 테이블입니다.

[주요 항목] 대상물관리번호(소방), 건축물대장관리번호(국토부), PNU(필지고유번호),
정제 도로명·지번주소, 좌표(위경도), 매칭근거(관리번호/PNU/주소/좌표), 매칭
신뢰도, 유효시작일·종료일

[지역 범위] 전국. 시·도 단위로 순차 구축 가능

[갱신 주기] 연 1회 이상(신축·멸실·용도변경 반영). 유효기간 컬럼으로 과거 시점을
재현할 수 있게 이력 관리

[형태] CSV. 특정소방대상물 1행당 1개 이상의 매칭 후보
```

## 융합 대상 데이터 (최소 2개 · 최대 5개)

| # | 데이터명 | 보유기관 |
|---|---|---|
| 1 | 특정소방대상물 현황 | 시·도 소방본부 (플랫폼 개방 중) |
| 2 | 화재안전특별조사(점검이력) | 시·도 소방본부 (플랫폼 개방 중) |
| 3 | 건축물대장 표제부 | 국토교통부 (건축HUB·공공데이터포털 개방 중) |
| 4 | 도로명주소·건물정보 | 행정안전부 (주소기반산업지원서비스) |
| 5 | 화재발생현황 | 시·도 소방본부 (플랫폼 개방 중) |

> 1~3번이 핵심이다. 4번은 주소 정규화 보조, 5번은 결과 검증용이다.
> **5개 모두 이미 공개되어 있고, 없는 것은 서로를 잇는 키뿐이다.**

## 융합 방법

```
[핵심] 잇는 키가 각자 있는데 서로에게 알려지지 않았습니다. 화재안전조사에는
대상물관리번호가 100% 있고, 건축물대장에는 전국 단일 식별자가 있습니다.
특정소방대상물에는 둘 다 없습니다.

[1단계] 특정소방대상물↔화재안전조사: 소방 내부에 이미 있는 대상물관리번호를
컬럼으로 추가해 직접 결합. 신규 수집 없이 완전 결합됩니다.

[2단계] 특정소방대상물↔건축물대장: ①소방 내부 대장의 건축물관리번호
②지번주소→PNU 변환 ③행안부 주소 API로 도로명 정규화 후 매칭 ④좌표 근접+
주용도 일치 순으로 적용하고, 행마다 매칭근거와 신뢰도를 기록합니다.

[3단계] 화재발생현황으로 결합 결과를 교차 확인하고, 신축·멸실을 유효기간
컬럼으로 관리해 과거 시점을 재현할 수 있게 합니다.

[원칙] 못 붙인 행은 비웁니다. 억지 매칭 한 건이 전체 신뢰를 무너뜨립니다.
```

## 활용 목적 및 활용방안

```
[누가] 소방본부 예방과, 소방청 정책부서, 화재보험·소방산업, 연구자

[상황1: 점검 효과 측정] 지금은 점검이력이 어느 건물의 것인지 알 수 없어 점검이
화재를 줄이는지 측정할 방법이 없습니다. 키가 있으면 점검받은 건물과 받지 않은
건물의 이후 화재율을 비교해 법정 점검주기 조정의 근거를 만들 수 있습니다.

[상황2: 점검 대상 선정] 건물 단위 화재위험 예측이 가능해집니다. 점검 대상이 곧
예측 단위가 되어 결과를 바로 계획으로 옮길 수 있습니다.

[상황3: 데이터 결합] 플랫폼의 유동인구·화재보험 위험도·소방IoT 데이터를 대상물에
붙일 수 있습니다. 조인 키 하나로 기존 데이터의 활용 범위가 넓어집니다.
```

## 제안 배경 및 차별성

```
[배경] 본 대회 출품작을 개발하며 실제로 막힌 지점입니다. 울산 화재안전특별조사
887,753행에는 대상물관리번호가 100% 있는데, 특정소방대상물 데이터셋(컬럼 14개)에는
그 번호가 없습니다. 주소도 없어 좌표 배정도 불가능해, 88만 행을 통째로 사용
포기했습니다.

[국제 사례] 미국 애틀랜타 Firebird(KDD 2016, NFPA 모범사례)와 뉴욕 FDNY RBIS가
공통으로 지목한 최대 난제가 "부서 간 공유되는 건물 ID 체계 부재"입니다. 두
사례 모두 주소 문자열 매칭으로 우회했고 매칭 오류를 한계로 남겼습니다.

[차별성] 미국이 못 푼 이유는 전국 단일 건물 식별자가 없어서입니다. 한국에는
건축물대장 관리번호가 이미 있습니다. 새로 수집하는 제안이 아니라, 각자 이미
가진 번호를 서로 알려 주자는 제안입니다.
```

## 데이터 확보·구축 방안

```
[1단계 — 즉시, 추가 수집 비용 없음] 특정소방대상물 데이터셋에 대상물관리번호
컬럼을 추가합니다. 이 번호는 소방 내부에 이미 있습니다(화재안전조사 데이터에
100% 실려 있는 것이 증거). 개인정보가 아닌 행정 식별자이므로 개방에 지장이
없습니다. 이 한 컬럼으로 점검이력 88만 행이 즉시 살아납니다.

[2단계 — 건축물대장 연계] 보유기관: 국토교통부(건축HUB 건축물대장정보 서비스,
공공데이터포털 개방 중). 경로는 ①소방 내부 대장의 건축물관리번호 ②PNU 경유
③행안부 주소기반산업지원서비스로 도로명 정규화 ④좌표 근접+용도 일치 순입니다.

[품질 원칙] 매칭하지 못한 건은 비우고 매칭근거를 남깁니다. 억지로 붙인 한 행이
그 데이터로 만든 모든 분석을 의심받게 만듭니다. 채움률보다 근거 공개가 중요합니다.
```

## 기대효과

```
[정책] 점검이 화재를 줄이는지 처음으로 측정할 수 있습니다. 법정 점검주기 조정,
예방 예산 성과 설명, 소방설비 지원 대상 선정에 건물 단위 근거가 생깁니다.

[플랫폼 고도화] 플랫폼 8개 카테고리 중 화재위험분석은 현재 데이터가 1건입니다.
새 데이터를 늘리기 전에 이미 있는 240여 건이 서로 붙게 하는 편이 값이 큽니다.
유동인구·화재보험 위험도·소방IoT·재난보험이 모두 대상물 단위로 연결됩니다.

[이용자 편의] 이용자가 각자 주소 문자열을 정제해 매칭하던 작업이 사라집니다.
같은 데이터로 서로 다른 결과가 나오는 일도 줄어듭니다.

[산업] 화재보험 요율 산정, 소방시설 관리업체의 대상물 이력 관리, 스타트업의
결합 분석이 가능해져 플랫폼 활용도 자체가 올라갑니다.
```

| 항목 | 실측 |
|---|---|

| 조사 데이터 점검일 | 2018-01-01 ~ 2021-12-16 (채움률 96%) |

| 조사 데이터 주소 | **없음** (좌표·격자 배정 불가) |
| 울산 특정소방대상물 | 34,858행, 컬럼 14개. 관리번호 계열은 `MLNO_YN`(다중이용업소 여부) 뿐 |

## B. 국제 사례 원문

> "여러 부서에서 모은 상업용 건물 자료를 결합하기가 어렵다 — 공유되는 건물 ID
> 체계도, 일관된 주소 형식도, 자료를 정확하고 최신으로 유지하는 내부 품질관리도
> 없기 때문이다."
> — Atlanta Firebird / FDNY RBIS 사례 보고

Firebird 는 8개 자료(화재·점검이력·범죄·주류/영업허가·인구사회·상업용 부동산·
필지 상태·Google Places)를 결합했고, 그중 **점검이력**이 핵심 학습 자료였다.
본 출품작이 8개 중 유일하게 쓰지 못한 것이 점검이력이다.

## C. 한국이 가진 것

국토교통부 건축HUB 건축물대장정보 서비스 표제부 응답에 전국 단일 건물 식별자가
들어 있다. 본 출품작에서 실제로 호출해 확인했다.

```xml
<platPlc>울산광역시 남구 삼산동 8-8번지</platPlc>
<mgmBldrgstPk>107814190</mgmBldrgstPk>   <!-- 건축물대장 관리번호 -->
<sigunguCd>31140</sigunguCd><bjdongCd>10600</bjdongCd>
```

## D. 이 제안이 우리 출품작을 어떻게 바꾸는가

출품작 **불씨예보(K-Firebird)** 는 500m 격자 단위로 화재위험을 예측해 상위 20%
구역으로 실제 화재의 68.5%를 포착한다. 격자에 머문 이유는 건물 단위로 내려갈
키가 없어서다.

건축물대장을 **읍면동 단위**로라도 붙여 노후도 피처를 만들어 측정해 봤으나
개선이 없었다(−0.8%p, 95% 신뢰구간 −2.53 ~ +0.98%p). 읍면동 단위로는 같은 동의
격자가 모두 같은 값이 되어 격자를 가르지 못하기 때문이다. **건물 단위 키가
있어야 풀리는 문제**라는 것을 측정으로 확인했다.
